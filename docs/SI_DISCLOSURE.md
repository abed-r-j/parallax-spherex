# Use of SI in ParallaX

NASA Space Apps 2026 uses the name "Super Intelligence (SI)" for what is usually called
artificial intelligence, and requires teams to say where and how such tools were used. This
page is that statement for ParallaX, by team ZENITH LABS.

## Short version

The software, documents and figures of this project were produced with the help of an SI
coding assistant (Claude, by Anthropic), directed by the team. The team defined the problem
and the approach and reviewed and ran everything. All results are computed by the project's
own code from real SPHEREx data. No SI-generated images, video, voices or faces are used.

## Which tool

One tool: Claude, a large language model by Anthropic, used as a coding and writing assistant
in the team's development environment. No image generator, voice generator, video generator
or other generative model was used. ParallaX itself contains no machine-learning model and
no language model: every step of the pipeline and the web app is ordinary, deterministic
numerical code that can be read and re-run.

## What the team did

* Chose the challenge and defined the problem: SPHEREx revisits every position at a
  different wavelength, so conventional blinking and subtraction confuse colour with change.
* Decided the approach: correct for colour with a per-pixel template instead of discarding
  frames, and prove or disprove the benefit with a three-way comparison on real data.
* Directed the work step by step, decided what to keep and what to drop, and decided to
  publish the unfavourable findings (see `RESULTS.md`, section 2.2).
* Ran the pipeline, the tests and the app on the team's own computer, and reviewed the code,
  the numbers and the documents.

## What the SI assistant did, under that direction

| Part | Role of the assistant |
|---|---|
| Python pipeline (`pipeline/src/parallax`, `pipeline/scripts`, `pipeline/tests`) | wrote most of the code and the tests, following the team's design; ran them and reported what failed |
| Web app (`web/src`, `web/scripts`) | wrote most of the code and the tests; took and inspected screenshots of the real build |
| Research notes | gathered and checked the challenge text, the rules, the archive interfaces and the literature; each claim was marked verified or unverified |
| Documents (this folder, `README.md`, the report, the submission texts) | drafted the text from the measured results; the team reviewed it |
| Figures | none are generated by an SI model. Every figure is a plot made by the project's code (matplotlib) from real SPHEREx data, or a screenshot of the running app |

## How it is marked

* Every source file written with the assistant carries the line "SI disclosure: written with
  the help of an SI coding assistant (Claude), checked by the team." in its header.
* The app's About page has a "Use of SI" section.
* The README, the project report and the submission form state it.
* There is no SI-generated image, video or audio in the project, so there is nothing to
  watermark. If that ever changes, the item will carry a visible "SI-generated" mark.

## What SI was not used for

* Not for producing any result. Every number in `RESULTS.md` is the output of
  `pipeline/scripts/run_ledger.py` and `run_validation.py` on real SPHEREx Level-2 images.
  Nothing is simulated in the judged path except the artificial test sources that the
  injection-recovery test adds to real frames, and those are labelled as such.
* Not for making images of the sky, of the spacecraft, of people, or of any logo or mission
  identifier.
* Not inside the tool: ParallaX makes no SI or machine-learning inference at run time.

## Attribution of outputs

ParallaX code. They are not NASA products and must not be attributed to NASA. NASA is not
